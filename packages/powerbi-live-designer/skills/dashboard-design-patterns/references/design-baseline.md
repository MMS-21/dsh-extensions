# Default analytical report design

Apply these adjustable defaults when the user has not supplied brand or report conventions. They supplement the pattern catalog; choose a different design when the task, device, or approved brief calls for it.

- Start with a 16:9 desktop overview (1280 × 720 as a planning canvas), then focused detail pages where needed. Keep comparisons together. Scrolling is acceptable when justified by the task or accessible presentation; it is not automatically a defect.
- Use Segoe UI or the host's established sans-serif. Start with a 24 pt page title, 14 pt visual titles, and 12 pt labels; verify readability at the actual viewing scale rather than shrinking text to make a page fit.
- Align components to an 8-unit spacing grid; use consistent outer margins and meaningful groups. Prioritize the user's questions over filling empty space or a fixed number of KPI cards.
- Prefer bars for category comparison, lines for temporal changes, and tables for exact lookup. Show units and comparison periods. Other representations require a task-based reason, not a popularity justification.
- Use a restrained neutral base with a consistent accent. The same business category keeps the same color across pages. Pair status color with text or symbols; distinguish unknown and missing values from zero.
- Use approved measures and formats. Rates need a denominator and a stated period; currency needs a unit. Identify proposed KPIs or ontology concepts as suggestions until the user confirms their meaning.
- Give every page a clear analytical purpose and visible filter context. Provide a discoverable way to reset filters where the adapter supports it. Add only interactions with a demonstrated task benefit.
- State the data source, relevant limitations, and known refresh time. An operation timestamp is not evidence of source-data freshness.
- Review keyboard access, reading order, contrast, alt descriptions, and layout at the intended viewport. Screenshot review alone cannot verify these interactions or mathematical correctness.

Completion: every planned visual has a business question, model binding, intended interaction, and observable acceptance check. Explain material deviations from these defaults in the design plan.
